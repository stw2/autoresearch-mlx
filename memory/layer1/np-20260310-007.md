## Assertion

At the current shallow anchor (`DEPTH=2`, `TOTAL_BATCH_SIZE=2**15`), changing one-head model width away from `128` dimensions did not improve `val_bpb`. Both narrowing to `64` dimensions and widening to `256` or `384` dimensions regressed, so the best-known local setting remains the incumbent 128-d one-head model.

## Conditions

- 5-minute training budget from `prepare.py`
- Apple Silicon MLX training stack in the repository default setup
- Best incoming anchor before this session: commit `5af9be75399cef8d24756f0faa6f901ec44d4f54`
- `DEPTH=2`, `TOTAL_BATCH_SIZE=2**15`, `DEVICE_BATCH_SIZE=16`, `WINDOW_PATTERN="SSSL"`, AdamW hyperparameters unchanged
- Width was varied by changing `ASPECT_RATIO` and `HEAD_DIM` together so each run stayed at exactly one attention head: 64-d, 128-d, 256-d, and 384-d

## Falsification

The explicit falsification run widened the model from 128 dimensions to 256 dimensions while keeping the shallow depth-2, one-head setup otherwise fixed. If the incumbent anchor were width-limited, this run should have improved on `1.431264`; instead it regressed to `1.452874`, cut completed optimizer steps from `2215` to `1500`, and increased peak memory from `18.6 GB` to `21.1 GB`. The even wider 384-d follow-up regressed further to `1.588286`, so the positive width-scaling hypothesis failed cleanly.

## Implications

The current shallow optimum appears to be constrained more by update budget than by one-head model width. Follow-up work should keep the 128-d width fixed unless another axis materially changes throughput, and should focus on factors like scheduling, windowing, or other training dynamics instead of widening or narrowing this shallow anchor.
