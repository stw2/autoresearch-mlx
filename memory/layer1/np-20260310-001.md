## Assertion

Under the current `model_dim = ceil(DEPTH * ASPECT_RATIO / HEAD_DIM) * HEAD_DIM` scaling rule, increasing `DEPTH` above the baseline of 4 does not improve `val_bpb` within the fixed 5-minute budget. The best result in this session came from the shallower `DEPTH=2` model, and a much deeper `DEPTH=6` model was substantially worse.

## Conditions

- 5-minute training budget from `prepare.py`
- Apple Silicon MLX training stack in the repository default setup
- Baseline control: `DEPTH=4`, `ASPECT_RATIO=64`, `HEAD_DIM=128`, `TOTAL_BATCH_SIZE=2**16`
- All runs changed only the `DEPTH` constant in `train.py`

## Falsification

The explicit falsification test was `DEPTH=2`, which should have underperformed if extra depth were helping. Instead it improved `val_bpb` from `1.616013` to `1.467048` while reducing peak memory from `21.2 GB` to `18.6 GB`, directly refuting the original hypothesis.

## Implications

This code path appears compute-limited under the 5-minute budget: shallower models train through many more optimizer steps and currently win despite having fewer parameters. Follow-up work should probe the shallow region first, for example `DEPTH=1-3` with width held or retuned explicitly, rather than spending more budget on deeper variants.
