## Assertion

At the current best shallow anchor (`DEPTH=2`, `TOTAL_BATCH_SIZE=2**15`), keeping `n_embd=128` as a single attention head is better than splitting it across 2, 4, or 8 heads. Every extra-head variant I tested regressed `val_bpb`, and the losses grew as the head count increased and the step budget collapsed.

- 5-minute training budget from `prepare.py`
- Apple Silicon MLX training stack in the repository default setup
- Best-known anchor commit before this session: `0ffed971505826db333698d3e411ad328d12d7b0`
- `DEPTH=2`, `TOTAL_BATCH_SIZE=2**15`, `ASPECT_RATIO=64`, `DEVICE_BATCH_SIZE=16`, AdamW hyperparameters unchanged
- `n_embd` stayed fixed at `128`, so all runs stayed at `3.5M` parameters; only `HEAD_DIM` and the implied attention-head count changed

## Falsification

The session started from the opposite hypothesis: `HEAD_DIM=32` (4 heads) might beat the 1-head control, while `HEAD_DIM=16` (8 heads) would be the failure case. The explicit falsification run at `HEAD_DIM=16` failed hard, regressing by `0.224611 bpb`, halving the completed optimizer steps (`1051` vs `2217`), and nearly doubling peak memory (`35.5 GB` vs `18.6 GB`). The closer disproof attempts at `HEAD_DIM=64` and `HEAD_DIM=32` also lost to the control, so the stronger negative conclusion survived all tested variants.

## Implications

For the current shallow optimum, the bottleneck still looks like update budget rather than attention expressivity. Follow-up work should keep the 1-head `HEAD_DIM=128` setting fixed unless we also change width or some other factor enough to offset the clear throughput penalty from extra heads.
