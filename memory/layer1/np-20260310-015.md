## Falsification

The falsification run increased `UNEMBEDDING_LR` to `0.006`, which should have won if the real problem were that the incumbent `0.004` was too low. It did not beat the incoming anchor, finishing `0.001590 bpb` worse, so the higher side did not overturn the negative conclusion. The stronger disproof attempt was the direct target run at `0.003`, which failed badly, and the further drop to `0.002` was worse still.

## Implications

For the current shallow anchor, there is no evidence that pushing `UNEMBEDDING_LR` below `0.004` helps. Future optimizer work should leave the unembedding learning rate at `0.004` for now and spend search budget on other axes, unless a later architectural change justifies revisiting this parameter.
