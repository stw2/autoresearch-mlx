## Assertion

At the current best shallow anchor (`DEPTH=2`, `TOTAL_BATCH_SIZE=2**15`, `HEAD_DIM=128`), changing the MLP expansion away from the incumbent 4x setting did not improve `val_bpb`. Narrower FFNs at 3x, 2x, and 1x all regressed, and the wider 6x falsification run only recovered part of the control-rerun drift while still missing the incumbent anchor by `0.005152 bpb`.

- This session changed only the MLP expansion ratio in `train.py`; all other optimizer and architecture settings were held fixed

## Falsification

The explicit falsification run widened the FFN to 6x. If the incumbent 4x expansion were merely underprovisioned, 6x should have exceeded the anchor. It did not: `val_bpb` improved slightly relative to the noisy same-session control rerun (`1.437553` vs `1.439098`) but still stayed `0.005152 bpb` worse than the incumbent anchor, so the negative conclusion survived the wider-model challenge.

## Implications

The current shallow optimum does not appear bottlenecked by FFN width. Follow-up work should keep the default MLP expansion fixed unless another axis changes enough to justify reopening this question, and future sessions should spend budget on other factors with less evidence saturation.
